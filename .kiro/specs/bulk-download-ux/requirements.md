# 要件定義書

## はじめに

大量のExcelファイル（30ファイル程度）を同時に解除する際のUXを改善する機能。処理結果が大量に表示されてスクロールが大変になる問題を解決し、ダウンロード状況の把握と一括ダウンロードを可能にする。

## 用語集

- **処理結果セクション**: 解除処理の結果を表示するUI領域
- **一括ダウンロード**: 複数の解除済みファイルをZIP形式でまとめてダウンロードする機能
- **ダウンロード済み状態**: ユーザーが個別にダウンロードしたファイルを視覚的に区別する状態

## 要件

### 要件1: 自動スクロール

**ユーザーストーリー:** ユーザーとして、解除ボタンを押したときにページ最上部に自動スクロールしたい。処理結果をすぐに確認できるようにするため。

#### 受け入れ基準

1. WHEN ユーザーが解除ボタンをクリック THEN システム SHALL 処理結果セクションのヘッダーがビューポート内に入るように `scrollIntoView({behavior:'smooth'})` でスクロールする
2. WHEN スクロールが完了 THEN システム SHALL 処理結果セクションが画面上部に表示される状態にする

### 要件2: ダウンロード済み表示とダウンロード期限表示

**ユーザーストーリー:** ユーザーとして、ダウンロードしたファイルを視覚的に区別したい。また、ダウンロード可能な残り時間を把握したい。どのファイルをダウンロードしたか、いつまでダウンロード可能かを確認できるようにするため。

#### 受け入れ基準

1. WHEN ユーザーがダウンロードボタンをクリック THEN システム SHALL 該当ファイルの状態を即座に「ダウンロード済み」に変更する
2. WHEN ファイルがダウンロード済み状態 THEN システム SHALL ボタンのテキストを「ダウンロード済み」に変更する
3. WHEN ファイルがダウンロード済み状態 THEN システム SHALL ボタンの背景色をグレーに変更する
4. WHEN ファイルがダウンロード済み状態 THEN システム SHALL ダウンロードボタンを再クリック可能な状態で維持する
5. WHEN ダウンロードAPIが失敗 THEN システム SHALL ボタンの状態を元に戻しエラーを通知する
6. WHEN 解除成功ファイルが表示される THEN システム SHALL 各ダウンロードボタンの右側にダウンロード期限のカウントダウンを表示する
7. WHEN カウントダウンが表示される THEN システム SHALL 「残り X分Y秒」形式で表示する
8. WHEN カウントダウンが1分未満 THEN システム SHALL テキスト色を赤色に変更して警告する
9. WHEN カウントダウンが0秒に到達 THEN システム SHALL 「期限切れ」と表示しダウンロードボタンを無効化する
10. WHEN カウントダウンが動作中 THEN システム SHALL 1秒ごとに表示を更新する

#### 技術仕様

- ダウンロード期限は `DOWNLOAD_EXPIRY_SECONDS` 定数（デフォルト300秒=5分）で管理する
- 定数は `app/config.py` で定義し、`app/main.py` のテンプレート変数 `download_expiry_seconds` として渡す
- `APP_CONFIG.downloadExpirySeconds` に注入し、JavaScript側で参照可能にする（既存の `clientConcurrency` 等と同様）
- `/unlock` APIの成功レスポンスに `expiresAt`（UTC ISO8601形式）フィールドを追加する
- フロントエンドは `expiresAt` を基準にカウントダウンを計算・表示する
  - 計算方法: `new Date(expiresAt) - new Date()` でUTC基準の残り時間を算出
  - ローカル時刻を基準にせず、サーバー起算のUTC時刻を使用することでタイムゾーンずれを防止
- JavaScriptで `setInterval` を使用して1秒ごとに更新
- カウントダウン開始: 各ファイルの `status=success` 表示時に開始する
- カウントダウン停止: 期限切れ時、結果クリア時、ページ離脱時に `clearInterval` でタイマーを停止する
- カウントダウン表示位置: ダウンロードボタンの右側、同じ行に配置

#### API仕様拡張（/unlock レスポンス）

成功時のレスポンスに期限情報を追加:
```json
{
  "fileName": "解除済みファイル.xlsx",
  "status": "success",
  "message": null,
  "downloadUrl": "/download/file-id-123",
  "expiresAt": "2025-12-01T12:05:00Z"
}
```

- `expiresAt`: ダウンロード期限（UTC ISO8601形式）
- フロントエンドは現在時刻との差分からカウントダウンを計算する

#### 補足

- ダウンロード済み状態はページリロードでリセットしてよい（セッション持ち越し不要、ローカル状態管理のみ）

### 要件3: 一括ダウンロード

**ユーザーストーリー:** ユーザーとして、解除成功したファイルを一括でダウンロードしたい。大量のファイルを効率的に取得できるようにするため。

#### 受け入れ基準

1. WHEN 解除成功ファイル（status=success）が2件以上存在 THEN システム SHALL 処理結果セクションのヘッダーに「一括ダウンロード」ボタンを表示する
2. WHEN 解除成功ファイルが1件以下 THEN システム SHALL 「一括ダウンロード」ボタンを非表示にする
3. WHEN ユーザーが一括ダウンロードボタンをクリック THEN システム SHALL status=success の全ファイルをZIP形式でダウンロードする
4. WHEN ZIPファイルを生成 THEN システム SHALL ファイル名を「解除済み_YYYYMMDD_HHMMSSZ.zip」形式にする（タイムスタンプはUTC）
5. WHEN 一括ダウンロードが HTTP 200 で完了 THEN システム SHALL 対象ファイルを全て「ダウンロード済み」状態に変更する
6. WHEN 一括ダウンロードが HTTP 206（部分成功）で完了 THEN システム SHALL 取得できたファイルのみ「ダウンロード済み」状態に変更し、取得できなかったファイルはそのまま維持する
7. WHEN 一括ダウンロードボタンがクリック中 THEN システム SHALL ボタンをローディング状態にし二重押下を防止する

#### 対象ファイルの定義

- 一括ダウンロード対象は `status=success` のファイルのみ
- 個別ダウンロード済みでもZIPに含める
- エラー/失敗ファイルは含めない

#### API仕様

- **エンドポイント:** `POST /download/bulk`
- **リクエスト形式:** `Content-Type: application/json`
  ```json
  {
    "fileIds": ["file_id_1", "file_id_2", ...]
  }
  ```
- **レスポンス（成功）:** HTTP 200, `Content-Type: application/zip`
  - ZIPファイルのバイナリストリームを返す
  - `Content-Disposition: attachment; filename="解除済み_YYYYMMDD_HHMMSSZ.zip"`
  
- **レスポンス（部分成功）:** HTTP 206, `Content-Type: application/json`
  - ZIPダウンロードURLとメタ情報をJSONで返す
  - フロントエンドは受信後、`downloadUrl` を使用してZIPをダウンロードする
  ```json
  {
    "status": "partial",
    "downloadUrl": "/download/bulk/temp-zip-id",
    "downloadedCount": 8,
    "missingCount": 2,
    "message": "2件のファイルが見つかりませんでした"
  }
  ```
  
- **レスポンス（エラー）:**
  - HTTP 400: fileIds が空、重複除去後0件、または件数上限（100件）超過
  - HTTP 500: ZIP生成失敗

#### 部分成功時の実装方針

- HTTP 206時は `Content-Type: application/json` でメタ情報を返す
- 生成されたZIPファイルは一時的に保存し、`downloadUrl` を返す
- フロントエンドは以下の手順でZIPをダウンロードする:
  1. `fetch(downloadUrl)` でZIPファイルを取得
  2. `response.blob()` でBlobオブジェクトを生成
  3. `URL.createObjectURL(blob)` で一時URLを作成
  4. `<a>` 要素の `href` に設定し、`download` 属性でファイル名を指定
  5. プログラムから `click()` を実行してダウンロード
  6. `URL.revokeObjectURL()` でメモリ解放
- この方式により、フロントエンドがメタ情報（missing数）を取得してUI通知できる
- アンカータグの直リンクではヘッダーを読めないため、fetch経由で取得する

#### 入力バリデーション

1. WHEN fileIds が空配列 THEN システム SHALL HTTP 400 を返す
2. WHEN fileIds に重複がある THEN システム SHALL 重複を除去してユニーク化する
3. WHEN fileIds の件数が100件を超える THEN システム SHALL HTTP 400 を返す

#### クリーンアップポリシー

- ZIP生成後も元の個別ファイルは既存の有効期限（5分）まで保持する
- 既存の個別ダウンロードURLはそのまま有効
- ZIP生成をもって元ファイルを削除しない
- **一時ZIPファイルの有効期限**: `DOWNLOAD_EXPIRY_SECONDS`（5分）に準拠
  - HTTP 206で返される `downloadUrl` は生成から5分間有効
  - 期限切れ後のアクセスはHTTP 404を返す
  - サーバー側で期限管理を行い、自動削除する

#### エラーハンドリング

1. WHEN ZIP生成に失敗 THEN システム SHALL HTTP 500とエラーメッセージを返す
2. WHEN ZIP生成に失敗 THEN システム SHALL UIでトースト通知を表示する
3. WHEN 一部のfile_idが存在しない/期限切れ THEN システム SHALL 存在するファイルのみでZIPを生成し、HTTP 206（JSON）で返却する
4. WHEN HTTP 206 を受信 THEN システム SHALL JSONから `missingCount` を取得し、「X件のファイルが見つかりませんでした」とUIで通知する
5. WHEN HTTP 206 を受信 THEN システム SHALL `downloadUrl` を使用してZIPファイルをダウンロードする

### 要件4: 処理結果のクリア

**ユーザーストーリー:** ユーザーとして、処理結果セクションをクリアしたい。新しいバッチ処理を開始する前に画面をリセットできるようにするため。

#### 受け入れ基準

1. WHEN 処理結果が1件以上表示されている THEN システム SHALL 処理結果セクション（`#results-section`）の下部に「処理結果をクリア」ボタンを表示する
2. WHEN 処理結果が0件 THEN システム SHALL 「処理結果をクリア」ボタンを非表示にする
3. WHEN ユーザーが「処理結果をクリア」ボタンをクリック THEN システム SHALL 処理結果セクション全体を非表示にする
4. WHEN 処理結果がクリアされる THEN システム SHALL 処理結果リスト（`#results-list`）の全アイテムを削除する
5. WHEN 処理結果がクリアされる THEN システム SHALL 一括ダウンロードボタンも非表示にする（存在する場合）
6. WHEN 処理結果がクリアされる THEN システム SHALL 実行中のカウントダウンタイマーを全て停止する（`clearInterval`）
7. WHEN 処理結果がクリアされる THEN システム SHALL 以下の状態を全てリセットする:
   - ダウンロード済みフラグ（全ファイル）
   - 保持している `downloadUrl` 配列
   - 一括ダウンロードボタンのローディング状態
   - 表示中のカウントダウン表示（DOM要素）
   - カウントダウンタイマーのID配列

#### UI配置

- 「処理結果をクリア」ボタンは処理結果セクション（`#results-section`）の最下部、結果リスト（`#results-list`）の直後に配置
- 既存の「ファイルをクリア」ボタン（ファイル一覧セクション）とは独立して動作
- ボタンスタイルは既存の「ファイルをクリア」ボタンと統一する

#### サーバー側ファイルの扱い

- 処理結果クリアはフロントエンド状態のみをリセットする
- サーバー側の一時ZIPファイルおよび個別ファイルは期限（5分）まで保持される
- ファイル削除はサーバーの有効期限管理に任せ、クリア操作では削除しない
- この方針により、既存の5分有効ルールと整合性を保つ
