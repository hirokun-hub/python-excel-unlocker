# 要件書

## はじめに

GitHub Actionsワークフローが最近実行されない問題を解決するため、ワークフロー設定の修正とGitHub Secretsの設定を行います。現在、プッシュ時に`deploy-platform.yml`が実行されるはずですが、シークレット設定の問題で失敗しています。

## 要件

### 要件1：ワークフロー実行エラーの解決

**ユーザーストーリー：** 開発者として、コードをプッシュした時にGitHub Actionsワークフローが正常に実行されることを期待します。

#### 受け入れ基準

1. **WHEN** `main`または`develop`ブランチにプッシュした時 **THEN** `deploy-platform.yml`ワークフローが正常に開始される
2. **WHEN** ワークフローが実行される時 **THEN** 必要なシークレットが正しく参照される
3. **IF** シークレットが未設定の場合 **THEN** 明確なエラーメッセージが表示される

### 要件2：GitHub Secretsの設定確認と修正

**ユーザーストーリー：** 管理者として、GitHub Actionsで必要なシークレットが正しく設定されていることを確認したいです。

#### 受け入れ基準

1. **WHEN** AWS関連のワークフローが実行される時 **THEN** `AWS_ACCESS_KEY_ID`と`AWS_SECRET_ACCESS_KEY`または`AWS_GITHUB_ACTIONS_ROLE_ARN`が利用可能である
2. **WHEN** Vercel関連のワークフローが実行される時 **THEN** `VERCEL_TOKEN`、`VERCEL_ORG_ID`、`VERCEL_PROJECT_ID`が利用可能である
3. **WHEN** バックエンドワークフローが実行される時 **THEN** `ALLOWED_USERS`シークレットが設定されている

### 要件3：ワークフロー設定の最適化

**ユーザーストーリー：** 開発者として、ワークフローが効率的に実行され、不要な処理がスキップされることを期待します。

#### 受け入れ基準

1. **WHEN** プルリクエストが作成された時 **THEN** デプロイ処理はスキップされ、テストのみが実行される
2. **WHEN** `develop`ブランチにプッシュした時 **THEN** development環境にデプロイされる
3. **WHEN** `main`ブランチにプッシュした時 **THEN** staging環境にデプロイされる
4. **IF** シークレットが未設定の場合 **THEN** デプロイ処理はスキップされ、テストのみが実行される

### 要件4：エラーハンドリングの改善

**ユーザーストーリー：** 開発者として、ワークフローが失敗した時に原因を特定しやすいエラーメッセージを受け取りたいです。

#### 受け入れ基準

1. **WHEN** シークレット設定エラーが発生した時 **THEN** 不足しているシークレット名が明確に表示される
2. **WHEN** AWS認証エラーが発生した時 **THEN** OIDC設定またはアクセスキー設定の確認方法が表示される
3. **WHEN** Vercel認証エラーが発生した時 **THEN** トークンの有効性確認方法が表示される
4. **WHEN** ワークフローが失敗した時 **THEN** GitHub Step Summaryに詳細な対処法が表示される

### 要件5：設定ドキュメントの更新

**ユーザーストーリー：** 新しい開発者として、GitHub Secretsの設定方法を理解し、正しく設定できるようになりたいです。

#### 受け入れ基準

1. **WHEN** 新しい開発者がプロジェクトに参加した時 **THEN** GitHub Secretsの設定手順が明確に文書化されている
2. **WHEN** AWS設定を行う時 **THEN** OIDC設定とアクセスキー設定の両方の手順が提供される
3. **WHEN** Vercel設定を行う時 **THEN** 必要なトークンとIDの取得方法が説明されている
4. **WHEN** 設定エラーが発生した時 **THEN** トラブルシューティングガイドが利用可能である
