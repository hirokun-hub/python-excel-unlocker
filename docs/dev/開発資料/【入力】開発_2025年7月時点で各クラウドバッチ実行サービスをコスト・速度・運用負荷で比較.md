### ⚙️ 評価前提

- **処理対象:** Excel 50件（[[一括解除バッチ]] を想定）
- **1件あたり実行時間:** 10秒（[[Python]]・[[msoffcrypto]]利用時の実測例）
- **コンテナ/関数サイズ:** 1 vCPU／512MB（比較単純化のため）
- **単発ジョブ方式:** 「最初のリクエスト→バッチ開始→終了でコンテナ破棄」

> ※これはあくまでコスト指標を揃えるための仮定。実測値が異なれば線形にスケール。

### 3. 評価ポイント

#### ☑️ 起動遅延
- [[Lambda]]：ほぼ瞬時（UX最優先なら有利）
- [[Cloud Run]] Startup Boostで9秒前後に短縮可
- [[Render]] One-Offは30秒超スタートがボトルネック

#### ☑️ コスト
- [[Cloud Run]]はあなたの50×10秒程度なら毎月無料枠内
- [[Fly.io]]は従量最安だが無料枠無し。月数百回超だとCloud Runより高くなる
- [[Lambda]]はGB-sec課金。メモリを512MBに抑えれば安価だが、INITフェーズも[[2025-08]]から課金対象

#### ☑️ 同時50件処理

| サービス        | 並列アプローチ                                            |
|----------------|:----------------------------------------------------------|
| Cloud Run      | concurrency=1で50インスタンス or concurrency=10で5インスタンス自動スケール  |
| Lambda         | 50invocations（余裕）                                      |
| Fly.io         | Machines APIで50台起動（制限≒300/組織）                   |
| Render OJ      | 50ジョブ発火可。ジョブキューは20同時実行が上限（超過は待機）|
| Railway        | 自動スリープだが高並列はProプラン推奨                      |

#### ☑️ 実装・運用負荷
- Render One-Off：既存Renderワークスペースをそのままテンプレートにでき、Webhookでジョブ起動→完了待ちが簡単
- Cloud Run Job：`gcloud run jobs execute`でバッチ実行。I/OはCloud Storage
- Lambda：関数サイズ（250MB unzip）・15分制限・VPC周りに注意
- Fly.io：Machines APIのsuspend/resumeを自前プロキシで叩く必要あり
- Railway：HTTPアプリとしてデプロイ→自動スリープ。Cronなどは別途

| 優先度 | 条件                                          | 推奨基盤                          |

### 5. あなたのプロジェクトへの具体的提案

1. **まずCloud Run JobsでPoC**
    - [[Dockerfile]]をそのまま持ち込み（`gcloud run jobs submit --image ...`）
    - [[GCS]]署名URLでファイル受渡し
    - `--tasks 50` オプションで50並列タスク自動生成
    - 実行時間を[[Cloud Logging]]で確認し、無料枠超過の有無を検証

2. **起動10秒がUX上NGならLambdaパスへ**
    - Python 3.12ランタイム＋SnapStart。依存ライブラリはzip layerに分割
    - S3 multipart upload/downloadで6MB超転送はHTTP Streaming（8/1課金適用）

3. **Renderエコシステム維持が最優先なら**
    - 既出のOne-Off Jobシーケンス（resume/suspend不要）を実装
    - フロントは[[Workers]]で30秒以上の待ちをプログレスUIに変換

4. **頻繁に50件×数分の重い処理が来る場合**
    - [[Fly.io]] Machines + `auto_stop_machines=true`で1ファイル→1Machineを並列起動
    - 1Machine 3秒起動なので合計待ち<15秒

---

### 6. まとめ

- 単発・低頻度なら[[Cloud Run Job]]がコストゼロ＋実装容易で圧倒的に有利
- 起動遅延<1秒がKPIなら[[Lambda]]。ただしGB-sec課金＋15分制限に注意
- [[Render]] One-Offはダッシュボードだけで完結する手軽さが魅力だが、30秒超の冷却時間を許容できるかが分かれ目
- [[Fly.io]]はコールドスタート3秒と単価が最も低いが、無料枠が無いので実行回数次第でCloud Runを逆転
