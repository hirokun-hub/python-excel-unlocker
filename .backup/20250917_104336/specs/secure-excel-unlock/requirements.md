# Secure Excel Unlock - 要件定義書

## はじめに

本ドキュメントは、パスワード付きExcelファイルを安全かつ効率的に解除するWebアプリケーション「Secure Excel Unlock」の要件を定義します。

## プロジェクト概要

### 背景
- NSC社内で、ソフトバンクから送られてくるパスワード付きExcelファイルの解除作業が頻繁に発生
- 約70名のスタッフが影響を受ける業務負荷
- iPhoneでは閲覧はできるが、解除・編集・保存ができない制約
- 手動での複数ファイル処理による時間的負荷

### 目的
- パスワード解除にかかる時間を最小化
- 全デバイス（iPhone/Android/PC/Mac）からの統一操作を実現
- パスワード解除への心理的ブロックを軽減
- 業務効率の向上と意思決定の迅速化

## 要件

### 要件1: 基本的なパスワード解除機能

**ユーザーストーリー:** NSCスタッフとして、パスワード付きExcelファイルを素早く解除したい。そうすることで、業務を滞りなく進められる。

#### 受入基準
1. WHEN ユーザーがExcelファイル（.xlsx/.xls）をアップロードし、パスワードを入力 THEN システムはファイルを解除して返す
2. WHEN 第一パスワードで解除に失敗 THEN システムは第二パスワードを自動的に試行する
3. WHEN 両方のパスワードで解除に失敗 THEN システムは明確な失敗理由を表示する
4. WHEN 解除処理が完了 THEN システムは解除済みファイルのダウンロードリンクを提供する

### 要件2: マルチデバイス対応

**ユーザーストーリー:** 現場スタッフとして、手元にある任意のデバイスから同じ操作でファイル解除を行いたい。そうすることで、場所や時間に制約されずに業務を進められる。

#### 受入基準
1. WHEN ユーザーがiPhone Safariからアクセス THEN 完全な機能（アップロード→解除→ダウンロード→保存）が利用できる
2. WHEN ユーザーがAndroid/PC/Macからアクセス THEN 同一のUI/UXで操作できる
3. WHEN モバイルデバイスから利用 THEN レスポンシブデザインで最適化された画面が表示される

### 要件3: 認証とアクセス制御

**ユーザーストーリー:** システム管理者として、許可されたユーザーのみがサービスを利用できるよう制御したい。そうすることで、セキュリティを確保できる。

#### 受入基準
1. WHEN ユーザーがアプリにアクセス THEN Googleアカウントでの認証が必要
2. WHEN 未登録のGoogleアカウントでアクセス THEN アクセスが拒否される
3. WHEN 事前登録されたGoogleアカウントでログイン THEN 全機能にアクセスできる
4. WHEN 管理者が新しいユーザーを追加 THEN 招待制でアカウントを登録できる

### 要件4: セキュリティとデータ保護

**ユーザーストーリー:** ユーザーとして、アップロードしたファイルとパスワードが安全に扱われることを確認したい。そうすることで、安心してサービスを利用できる。

#### 受入基準
1. WHEN ファイルがアップロード THEN S3署名付きURLを使用した安全な転送が行われる
2. WHEN パスワードが送信 THEN HTTPS通信で暗号化される
3. WHEN 処理が完了 THEN 入力ファイルは即座に削除される
4. WHEN ログが記録 THEN パスワードやファイル名などの機密情報は含まれない

### 要件5: パフォーマンスと可用性

**ユーザーストーリー:** ユーザーとして、迅速な処理と安定したサービスを期待する。そうすることで、業務の流れを止めることなく作業できる。

#### 受入基準
1. WHEN 標準的なExcelファイル（<20MB）を処理 THEN P95で8秒以内に完了する
2. WHEN 解除に成功 THEN 成功率90%以上を維持する
3. WHEN システムエラーが発生 THEN 適切なエラーメッセージと復旧手順を表示する
4. WHEN 複数ユーザーが同時利用 THEN 最大50の同時実行をサポートする

### 要件6: 複数ファイル処理（将来拡張）

**ユーザーストーリー:** ユーザーとして、複数のExcelファイルを一度に処理したい。そうすることで、大量のファイル処理を効率化できる。

#### 受入基準
1. WHEN 複数ファイルが選択 THEN フロントエンドで順次処理される
2. WHEN バッチ処理中 THEN 進捗状況がリアルタイムで表示される
3. WHEN 一部ファイルが失敗 THEN 成功したファイルは正常にダウンロードできる
4. WHEN 処理が完了 THEN 全体の処理結果サマリーが表示される

## 非機能要件

### セキュリティ要件
- AWS S3のパブリックアクセスブロック有効化
- 署名付きURLの有効期限60秒
- CORS制限の適用
- 最小権限IAMポリシーの適用

### パフォーマンス要件
- P95処理時間: 8秒以内
- 最大ファイルサイズ: 20MB
- 同時実行数: 50
- 初回解除成功率: 90%以上

### 可用性要件
- サービス稼働率: 99%以上
- 障害復旧時間: 1時間以内
- データ保持期間: 処理完了後即時削除

## 対象外範囲

以下の機能は本プロジェクトの対象外とします：

1. **パスワード総当たり攻撃機能** - セキュリティ上の理由により実装しない
2. **シート保護解除機能** - 開封パスワード解除のみに限定
3. **ファイル形式変換機能** - Excel形式の解除のみに集中
4. **長期データ保存機能** - 処理完了後は即時削除
5. **有料課金機能** - 社内利用のため無料提供

## 成功指標（KPI）

1. **利用率**: 月間アクティブユーザー数
2. **処理成功率**: 初回解除成功率 ≥ 90%
3. **処理時間**: P95処理時間 ≤ 8秒
4. **ユーザー満足度**: 定性的フィードバック
5. **エラー率**: 失敗理由の分類と改善

## 制約事項

### 技術的制約
- AWS Lambda実行時間制限（最大15分）
- S3オブジェクトサイズ制限
- API Gateway制限

### 運用制約
- 社内利用のみ（外部公開なし）
- 管理者による手動ユーザー登録
- 個人負担によるインフラ費用

### 法的制約
- 権限を有するファイルのみ処理対象
- 既知パスワード候補のみ使用
- 社内情報取り扱いポリシー準拠
